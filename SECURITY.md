# Security Policy

## Supported Versions

blackvuesync provides best-effort support for the current stable release only, through the public [GitHub Issues](https://github.com/acolomba/blackvuesync/issues) tracker. No response time, resolution time, continued compatibility, or service-level agreement (SLA) is promised.

Routine fixes are not backported to older release lines. If you report a problem, reproduce it on the current stable release first.

When filing an issue, include the blackvuesync version, the Python version, reproduction steps, and redacted logs. Never include credentials or tokens.

## Reporting a Vulnerability

Do not open a public issue for a security vulnerability. Instead, use GitHub's private Security Advisories feature:

<https://github.com/acolomba/blackvuesync/security/advisories/new>

A private report keeps the details out of the public tracker until a fix is ready. Describe the issue and its impact, and share only the minimum information needed to reproduce it.
